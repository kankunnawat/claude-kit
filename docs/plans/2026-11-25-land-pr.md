# Land PR skill: build plan

Date: 2026-11-25.
Spec: `docs/specs/2026-11-25-land-pr-design.md`, decisions approved by Kan on 2026-11-25.

## Goal

Kan types `/land-pr` on an open PR and the session takes it through review and fixes to merge-ready.
The worktree stays while the PR is open and goes when `land-pr` ends, or when the PR is merged or closed.

## Shape

Two PRs, one per repo, built in parallel.
Each implementer works in its own worktree and never merges.

| PR | Repo | Branch | Holds |
|---|---|---|---|
| A | claude-kit | `feat/land-pr` | the new skill, `/finish` step 7, the `worktrees` skill text, the README row |
| B | dotfiles | `feat/worktree-keep-until-land` | the sweep script and its test, two rule lines |

PR B does not depend on PR A's code.
The two rule lines in PR B describe `/finish` as PR A changes it, so Kan merges B after A.

## The one piece of data

`/finish` step 7 and the sweep both decide from one fact: the state of the branch's PR, as `gh` reports it.

| PR state | `/finish` step 7 | Sweep, in-repo worktree roots |
|---|---|---|
| none | skip, as today | as today, by commit reachability |
| open | keep, unless `land-pr`'s close-out asks | keep |
| merged or closed, head SHA equals HEAD | remove | remove the worktree, keep the branch |
| merged or closed, head SHA differs | n/a (`/finish` already needs origin tip equal to HEAD) | keep |

## Assumptions and recovery

- `gh` and `timeout` are on the sweep's PATH under launchd. The sweep already calls both for the t3code roots, and without them the new path keeps the worktree.
- Removing a worktree is recoverable: the branch stays, the worktree was clean, and `land-pr` step 1 rebuilds it. No step deletes a branch or forces a removal of uncommitted work.
- Each PR reverts on its own with one `git revert`.

## Deviations

- The spec names `skills/worktrees/` as the home of the cleanup. The code that removes worktrees on a schedule is `worktree-sweep.sh` in dotfiles, so the change goes there and the `worktrees` skill only gets its text updated.
- The sweep already removes a worktree with a merged PR under the t3code and Codex roots. This plan adds the same rule, plus closed PRs, to the in-repo roots only.

## Not yet specified

- Whether the t3code and Codex roots should also treat a closed, unmerged PR as done. Today they wait for the idle rule.

## Out of scope

- Linking `land-pr` by `install.sh` on other machines, and the installed copy of the pstack rule file. Both follow after Kan merges.
- Any change to `merge-agent`, `babysit-pr`, `sol-loop`, `full-send` or `lead`.
- Deleting branches.
