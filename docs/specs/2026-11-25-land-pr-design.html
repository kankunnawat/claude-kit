Approve: one verb, /land-pr, takes an open PR through review and fixes to merge-ready

It follows the repo's own PR playbook where one exists. Where none exists it offers to draft one, and reviews the PR by risk tier either way.

1 · Today

Work stops when the PR opens

Every piece of the review loop exists, but no verb starts from an open PR and runs them in order. Each repo needs a different one.

The worktree is usually gone by then, so each fix also begins by rebuilding it by hand.

2 · The change

One verb runs the middle

It follows the repo playbook, or offers to draft one. The reviewer is always a session that did not write the change. The skill grants no merge right: your guardrails and the merge guard still decide.

Names: skills/land-pr/SKILL.md, reusing merge-agent.py doctor and precheck

3 · How it runs

Ten steps, three ways in

  1. 1Find the PR. The worktree is still there; rebuild it from the kept branch only if it is gone.
  2. 2Check the repo. It has a playbook: follow it with its own tools, including any end-to-end run or TLA+ check it names. It has none: ask "Draft one now?" and go on. Not on GitHub: print the repo's own command and stop.
  3. 3Set the risk tier from the diff: low, medium or high. A reviewer can raise it, never lower it.
  4. 4Round 1: fresh review of the whole PR. A high PR gets a second reviewer for security.
  5. 5Label every finding Fix, Note or Dismiss. Only Fix changes code. A new test that cannot fail is a Fix.
  6. 6Commit the fixes, then one fresh review of the fix commits. No round 3.
  7. 7Proof by tier. Low: tests and green CI. Medium and high: also run the change the way a user would. With no verification skill, the session runs it and shows the command and output.
  8. 8Post the verdict. It names the tier and the last commit a reviewer read, so a later commit means "not yet".
  9. 9Merge where your guardrails allow it, pinned to that commit. A high PR always stops for you.
  10. 10Close with /finish, which removes the worktree. If you said yes in step 2, the playbook PR is drafted now and waits for you.

The loop never ends, and the PR grows one small fix at a time.

Already decided

  • A new skill, not a fold into /finish or merge-agent.
  • The name is land-pr, since pr-gate is taken by a repo's own skill.
  • One round of fixes, then one review of those fixes.
  • No repo's gate, tier rule or verdict format changes.
  • It runs only when you type it. No workflow chains into it.
  • A repo with no playbook is asked "Draft one now?" on every run, and the built-in tiers review the PR either way.
  • Three risk tiers, read from the playbook template merge-agent already ships.
  • TLA+ and other formal checks run only where a repo's playbook names them.
  • A high-risk PR always stops for you.
  • In a solo repo with no gate, it merges a low or medium PR after a pass.
  • /finish keeps the worktree while the PR is open. You still type /land-pr.
  • With no verification skill, the session runs the change and shows the output. A change that needs the screen or a real account stops for you.

Left for later: what the author's session does in hausback while it waits for a signer.

Not in this change: a formal check in the built-in loop, writing the playbook inside this skill, remembering a "not now" answer, chaining it onto other workflows, releases and deploys, stacked PRs, a queue of PRs, other people's PRs.
