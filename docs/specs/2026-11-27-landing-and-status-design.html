Approved: close the gaps between review, merge and settle

A ready PR gets a merge agent or a clear ask, a thread with an open PR stays in view, and every status reply starts with the one thing you should do.

What changes

+
Status replies: the first line is your next action, or "nothing needs you". At most six lines, plain words.
+
No merge agent open when a lead hands over a PR: it starts one where the area's manual allows it in your own dated words, with a brief that names no PR. Otherwise it asks you first.
+
land-pr accepts a passing review already recorded at the PR's head, only from a reviewer session it can read that did not write it.
+
A close-out with its PR still open leaves the thread in view, unless a live lead owns that repo.
+
The tier tool runs before any review. The hold file is one command, run first. Night mode shows in the machine budget.
+
A lead held at three asks may still use free slots on its own work that needs nothing from you. It starts nothing new.
+
A settle keeps an unanswered rule proposal in the queue.
+
CI runs three more existing tests and two new ones. Area logs keep seven days; older lines go to a monthly file.
=
The merge guard, the hooks and merge-agent.py. Approval rules too, except one new path: a lead may start a merge agent under a standing approval you wrote in the area's manual.

Risk → answer

A lead starts a merge agent you did not want.
Only under a standing approval written in the area's manual, with its date and scope. Otherwise it asks.
land-pr trusts a review it should not.
Stricter than the merge agent: the repo's format, a pass, this exact head, and a reviewer session it can read that did not write the change. Anything else runs a fresh review.
A thread stays open forever.
It stays only while its PR is open. A live lead that owns the repo lets it settle.
Rotating the log loses lines.
The archive is written and checked before the area file is rewritten, and a rerun adds no duplicate. Nothing old means nothing changes.

Decided

  • One status shape, kept in the owner contract (you, 27 Nov).
  • A merge agent starts on its own only under a written standing approval (you, 27 Nov).
  • land-pr may accept a recorded verdict in place of its own first review (you, 27 Nov).
  • No change to the merge guard, the hooks or merge-agent.py (you, 27 Nov).

Left for later: how a lead tells that a merge agent runs for its repo, beyond the thread list; whether the status shape also binds the land-pr and merge agent reports.

Not in this change: a daily fresh thread; how many reviewers re-review a fix; a base freshness check; any change to the merge script, the merge guard, hooks, dotfiles or brain repos.
